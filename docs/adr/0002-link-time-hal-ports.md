# ADR-0002 Link-time HAL ports

- Status: accepted
- Date: 2026-11-18

## Context

The firmware must run on more than one MCU ({need}`SYS-006`) and must test on a PC ({need}`SYS-008`). The hardware boundary needs an interface that a port can implement and a test can replace. Two shapes fit.

| | Function-pointer table | Link-time port |
| --- | --- | --- |
| Interface | A `struct` of function pointers passed to the BSP | Plain functions declared in `src/hal/*.h` |
| Pick the implementation | At run time | At link time, by the build choosing `src/hal/port/<mcu>/` |
| Two different PWM drivers in one image | Yes | No |
| Call cost | One indirect call | One direct call, inlinable with LTO |
| Test double | Hand-written fake table | Generated by CMock from the header |
| Misconfiguration | A `NULL` pointer at run time | A link error |

## Decision

Use link-time ports. Each HAL header in `src/hal/` declares functions that take a small integer channel or pin ID. Each MCU gets a directory `src/hal/port/<mcu>/` that defines those functions. The build compiles exactly one port.

Only files in `src/hal/port/` include vendor headers. `tools/check_layers.py` fails the build otherwise ({need}`SWR-ARC-001`).

## Consequences

- A missing HAL function is a link error, not a crash on the target.
- CMock mocks the HAL headers directly, so `tests/unit/bsp/test_bsp.c` needs no hand-written fakes.
- One image cannot mix two implementations of the same HAL interface. A board that needs that, for example an external PWM chip next to the MCU timers, would need the BSP to dispatch on channel ID inside its port. Revisit this ADR if that happens.
- `src/hal/port/host/` is a full port. It runs the same `app`, `domain` and `bsp` code against a simulated motor.
